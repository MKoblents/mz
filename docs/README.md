## Описание варианта
- `forth` -- синтаксис языка Forth с обратной польской нотацией.
    - Требуется поддержка процедур.
    - Требуется поддержка `execution token`.
- `stack` -- система команд должна быть стековой:
    - Вместо регистров используется стек.
    - Это не исключает и не заменяет наличие памяти команд и памяти данных.
- `neum` -- фон Неймановская архитектура.
- `mc` -- microcoded.
    - В отчёте необходимо задокументировать уровень микроинструкций.
    - Микрокод должен быть сохранён в отдельной памяти для микропрограмм.
    - Модель процессора должна исполнять микрокод.
- `stream`
    Ввод-вывод осуществляется как поток токенов (как во Wrench). Есть в примере. Логика работы:
    - При старте модели у вас есть буфер, в котором представлены все данные ввода (`['h', 'e', 'l', 'l', 'o']`).
    - При обращении к вводу (выполнение инструкции) модель процессора получает "токен" (символ) информации.
    - Если данные в буфере кончились -- останавливайте моделирование.
    - Вывод данных реализуется аналогично, по выполнении команд в буфер вывода добавляется ещё один символ.
    - По окончании моделирования показать все выведенные данные.
    - Логика работы с буфером реализуется в рамках модели на Python.
- `mem` -- memory-mapped (порты ввода-вывода отображаются в память и доступ к ним осуществляется штатными командами),
    - отображение портов ввода-вывода в память должно конфигурироваться (можно hardcode-ом).
- `pstr` -- Length-prefixed (Pascal string)
- `alg1` -- `is_prime`, `format_string`.
- `cache` -- работа с памятью реализуется через кеш.
    - Скорость доступа к кешу -- 1 такт, к памяти -- 10 тактов.
    - Необходимо реализовать алгоритм, демонстрирующий работу с кеш памятью и её влияние на производительность -- подойдёт `linear_filter` из [wrench variants](https://github.com/ryukzak/wrench/blob/master/variants.md) (повторное чтение соседних элементов окна создаёт заметную временную локальность).

## Язык программирования

### Синтаксис

Синтаксис в расширенной форме Бэкуса-Наура. Слова разделяются пробельными символами, регистр букв различается.

```ebnf
program     ::= { top_item } ;

top_item    ::= definition | data_decl | include | statement ;

include     ::= "include" file_name ;

definition  ::= ":" name { item } ";" ;

data_decl   ::= "variable" name
              | "create" name
              | number "constant" name
              | number "allot"
              | number "," ;

statement   ::= number | name | string_lit | tick ;

item        ::= number | name | string_lit | tick | char_lit | "recurse" | control ;

control     ::= "if" { item } [ "else" { item } ] "then"
              | "begin" { item } "until"
              | "begin" { item } "again"
              | "begin" { item } "while" { item } "repeat"
              | "do" { item } "loop"
              | "?do" { item } "loop" ;

tick        ::= ( "'" | "[']" ) name ;
char_lit    ::= ( "[char]" | "char" ) char ;
string_lit  ::= 's"' text '"' | '."' text '"' ;

number      ::= [ "-" ] digit { digit } | "0x" hex { hex } | "$" hex { hex } ;
comment     ::= "\" { any_char } end_of_line | "(" { any_char } ")" ;
```

Комментарии удаляются на этапе токенизации. В `s"` и `."` после ключевого слова идёт ровно один пробел, текст заканчивается первой закрывающей кавычкой.

### Семантика

**Стратегия вычислений.** Все слова работают со стеком данных. Число кладёт себя на стек, слово снимает свои аргументы и кладёт результаты. Запись `a b +` вычисляется слева направо: `a`, затем `b`, затем сложение. Определение слова (`: имя ... ;`) компилируется в подпрограмму, вызов слова это вызов подпрограммы, возврат делает `;` (или `exit`). Строгость вычислений: каждое слово вычисляется ровно тогда, когда до него дошло выполнение, ленивых вычислений нет.

Программа выполняется так: сначала загружаются все определения, затем по порядку выполняются выражения, записанные вне определений (они образуют «главную часть» программы), и в конце выполняется `bye`, а если его нет, транслятор допишет остановку сам.

**Области видимости.** Один глобальный словарь. Слово становится доступным сразу после `:` (поэтому рекурсия возможна и по имени, и через `recurse`). Пользовательское слово перекрывает встроенное с тем же именем. Локальных переменных нет: промежуточные значения живут на стеке данных и на стеке возвратов. Переменные, константы и буферы глобальные.

**Типизация.** Типов нет. Любое значение это 32-битное слово. Числа знаковые или беззнаковые определяется операцией (`<` знаковое сравнение, `u<` беззнаковое). Результат сравнения: `-1` (истина) или `0` (ложь). Адрес это обычное число. Один символ занимает одно слово.

**Литералы.**

| Вид | Запись | Значение |
|---|---|---|
| Десятичное число | `42`, `-5` | число |
| Шестнадцатеричное | `0xFF`, `$FF` | число |
| Символ | `[char] A` | код символа (65) |
| Строка | `s" text"` | адрес строки (pstr) в памяти данных |
| Печатаемая строка | `." text"` | то же и вызов печати строки (слово `pstr-type` из библиотеки) |
| Имя константы | `max-n` | значение константы |

**Слова во время трансляции** (работают вне определений):

| Слово | Действие |
|---|---|
| `include файл` | подставляет токены другого файла |
| `variable имя` | выделяет в памяти данных одно слово (нулевое) и называет его адресом |
| `create имя` + `n allot` | выделяет `n` байт (кратно 4), имя возвращает адрес начала |
| `n ,` | добавляет в память данных слово со значением `n` |
| `n constant имя` | константа, подставляется как литерал |
| `cells` | умножает число на 4 (при применении вне определений вычисляется при трансляции) |

**Execution token.** Слово `'` (внутри определения `[']`) кладёт на стек адрес слова. Слово `execute` снимает адрес со стека и вызывает слово по нему. Адрес слова это адрес его первой инструкции.

**Управляющие конструкции:**

| Конструкция | Поведение |
|---|---|
| `if A else B then` | снимает флаг; если 0, выполняется `B`, иначе `A` |
| `begin A until` | повторять `A`, пока снятый флаг равен 0 |
| `begin A again` | бесконечный цикл |
| `begin A while B repeat` | повторять, пока флаг после `A` не равен 0 |
| `limit start do A loop` | цикл со счётчиком от `start` до `limit-1` (верхняя граница не включается), `i` даёт текущий индекс |
| `limit start ?do A loop` | то же, но при `limit = start` цикл пропускается |

**Встроенные слова.**

| Группа | Слова |
|---|---|
| Стек данных | `dup drop swap over rot 2dup 2drop` |
| Арифметика | `+ - * / mod 1+ 1- negate` (деление знаковое, с усечением к нулю) |
| Логика, сдвиги | `and or xor invert lshift rshift` (`rshift` логический) |
| Сравнения | `= <> < > <= >= u< 0= 0< 0>` |
| Память | `@ !` (слово по адресу) |
| Стек возвратов | `>r r> r@ i` |
| Управление | `execute exit recurse bye` |
| Ввод-вывод | `key` (прочитать символ), `emit` (вывести символ), `cr`, `space` |
| Константы | `true` (−1), `false` (0) |

**Библиотека `examples/lib.fs`** (на самом Forth): `digit?`, `read-num` (число без знака), `read-int` (со знаком), `print-num`, `pstr-type` (печать pstr), `read-pstr` (чтение строки до перевода строки в pstr).

**Ограничения диалекта:** нет `leave`, `+loop`, `j`; нет вложенных определений; управляющие конструкции допустимы только внутри определений; `allot` и `,` должны идти сразу за `create`; нет байтовых операций (`c@`, `c!`): символ это слово. В `format_string` не поддерживается `%%`.

## Организация памяти

### Модель памяти

- Машинное слово 32 бита. Память байтовая, 64 КиБ (`0x0000–0xFFFF`), одна на код, данные и стеки (фон Нейман), **однопортовая**: за такт одно обращение.
- Все обращения словами по адресам, кратным 4. Невыровненный доступ вызывает ошибку.
- Доступ к памяти идёт через кеш, кроме портов ввода-вывода.

**Регистры:**

| Регистр | Назначение                                                        |
| ------- | ----------------------------------------------------------------- |
| `T`     | вершина стека данных                                              |
| `S`     | второй элемент стека данных                                       |
| `SP`    | указатель на стек данных в памяти (на первую свободную ячейку)    |
| `R`     | вершина стека возвратов                                           |
| `RSP`   | указатель на стек возвратов в памяти (на первую свободную ячейку) |
| `PC`    | счётчик команд (байтовый адрес)                                   |
| `IR`    | регистр текущей инструкции                                        |
| `AR`    | регистр адреса памяти                                             |
| `DR`    | регистр данных памяти                                             |
| `SR`    | флаги `N Z V C`                                                   |

В памяти нет отдельной области «инструкций» и «данных»: они лежат подряд в одном образе. Прерываний нет (ввод-вывод `stream`).

### Карта памяти

```text
0x0000  ┌──────────────────────────────┐
        │ jmp <точка входа>            │  всегда первая инструкция
        │ код определений слов         │
        │ код главной части (entry)    │  заканчивается halt
        ├──────────────────────────────┤
        │ статические данные           │  строки pstr, переменные,
        │                              │  буферы, литералы > 24 бит
        ├──────────────────────────────┤  граница образа: 0xE000 (максимум)
        │ свободная память             │
        │ ...                          │
0xF7FC  │ стек данных (вниз)           │  SP при старте
0xFBFC  │ стек возвратов (вниз)        │  RSP при старте
0xFFF0  │ порт ввода  (чтение)         │  MMIO
0xFFF4  │ порт вывода (запись)         │  MMIO
0xFFFF  └──────────────────────────────┘
```

Границы стеков не проверяются: переполнение стека в область данных это ошибка программиста.

### Стек данных: вершина в регистрах

Первый элемент `T` и второй `S` хранятся в регистрах. Третий и далее в памяти, начиная с адреса `SP + 4` (`SP` указывает на **первую свободную** ячейку, стек растёт вниз). Глубину стека модель не отслеживает: при старте `T = S = 0`, а «пустой» стек выглядит как стек с двумя нулями (пустой стек и два лежащих нуля неразличимы, снятие значений с пустого стека является ошибкой программиста).
### Стек возвратов

Регистр `R` хранит верхний элемент, остальное лежит в памяти по `RSP` (растёт вниз, `RSP` указывает на первую свободную ячейку). 
Адрес возврата кладётся в `R` как значение `PC` на момент выполнения `call`: к этому времени `PC` уже указывает на следующую инструкцию.

### Как программа и данные отображаются на память

**Литералы.** Число, помещающееся в знаковые 24 бита (`−8 388 608 … 8 388 607`), входит в операнд инструкции `push` (непосредственная адресация). Остальные числа транслятор помещает в память данных (одинаковые значения хранятся один раз) и генерирует `push <адрес>` и `load`. Многословных литералов нет: 64-битные числа программа хранит как пару слов (см. `examples/double.fs`).

**Строки.** Строка `s" Hello"` хранится в памяти данных в формате pstr: слово с длиной, затем по слову на символ. В код попадает только `push <адрес строки>`. Одинаковые строки хранятся один раз. Строки лежат подряд в порядке первого появления в программе.

**Константы.** Констант в памяти нет: `5 constant five` запоминается транслятором, а каждое использование превращается в `push 5`.

**Переменные и буферы.** Отображаются в статическую память (в регистры не отображаются, регистров общего назначения нет). `variable x` выделяет одно слово, `create buf n allot` выделяет `n` байт. Имя переменной в тексте превращается в `push <адрес>`. Порядок в памяти соответствует порядку объявления. Временные значения программа держит на стеках.

**Инструкции.** Лежат с адреса 0 подряд: сначала `jmp` на точку входа, затем определения слов в порядке записи, затем код главной части. Данные идут сразу после кода.

**Процедуры.** Слово `: имя ... ;` занимает непрерывный участок кода, заканчивающийся `ret`. Вызов: `call <адрес>`, адрес возврата сохраняется на стеке возвратов. Рекурсия работает без ограничений, кроме размера стека.

**Прерывания.** Отсутствуют.

**Порты ввода-вывода (`mem`).** Находятся в памяти по фиксированным адресам `0xFFF0` (чтение даёт код следующего символа ввода) и `0xFFF4` (запись добавляет символ в выходной буфер). Адреса заданы константами в `isa.py`. Слова `key` и `emit` транслируются в `push <порт>; load` и `push <порт>; store`. Обращения к портам не проходят через кеш.

## Система команд

### Особенности процессора

- **Классификация:** стековая система команд, операнды неявно берутся со стека. Инструкции одного размера (32 бита), у большинства операнда нет. Кодирование инструкций фиксированное, управление микропрограммное.
- **Типы данных:** единственный тип, 32-битное слово.
- **Адресация:** абсолютная (операнд инструкций `call`, `jmp`, `jz`, `jnz`), непосредственная (`push`), стековая (все остальные). Доступ к данным в памяти: адрес берётся со стека (`@`, `!`).
- **Ввод-вывод:** отображён в память.
- **Поток управления:** `PC` увеличивается на 4 при выборке каждой инструкции; условные и безусловные переходы по абсолютным адресам; вызов и возврат через стек возвратов.
- **Прерываний нет.**

### Кодирование инструкций

Каждая инструкция это одно 32-битное слово:

```text
 31      24 23                           0
┌──────────┬───────────────────────────────┐
│  опкод   │ операнд (24 бита, со знаком)  │
└──────────┴───────────────────────────────┘
```

Операнд используется только инструкциями `push`, `call`, `jmp`, `jz`, `jnz` (в остальных он равен 0). Знак операнда расширяется до 32 бит при чтении в АЛУ. Образ программы хранится в бинарном файле: слова подряд, порядок байт little-endian (младший байт первым). Опкод `0x00` это `halt`: память, заполненная нулями, останавливает процессор.

### Набор инструкций

Колонка «микрокоманд» это число микрокоманд тела инструкции; колонка «мин. тактов» это полный цикл выполнения при всех попаданиях кеша: 4 микрокоманды выборки, тело и дополнительные 9 тактов ожидания на каждую запись в память (запись сквозная, она всегда идёт в RAM за 10 тактов).

| Опкод | Команда | Слово Forth | Действие | Микрокоманд | Мин. тактов |
|---|---|---|---|---|---|
| `00` | `halt` | `bye` | остановка | 1 | 5 |
| `01` | `dup` | `dup` | положить копию `T` | 4 | 17 |
| `02` | `drop` | `drop` | снять значение | 4 | 8 |
| `03` | `swap` | `swap` | обменять `T` и `S` (через `DR`) | 3 | 7 |
| `04` | `over` | `over` | положить копию `S` | 5 | 18 |
| `05` | `ret` | `;`, `exit` | вернуться из подпрограммы | 4 | 8 |
| `06` | `tor` | `>r` | со стека данных на стек возвратов | 8 | 21 |
| `07` | `fromr` | `r>` | со стека возвратов на стек данных | 8 | 21 |
| `08` | `rfetch` | `r@`, `i` | копия `R` на стек данных | 5 | 18 |
| `09` | `exec` | `execute` | вызвать слово по адресу из `T` | 9 | 22 |
| `0A` | `push imm` | литерал | положить константу (операнд 24 бита) | 5 | 18 |
| `10` | `call addr` | имя слова | вызвать подпрограмму | 5 | 18 |
| `11` | `add` | `+` | `T ← S + T` | 4 | 8 |
| `12` | `sub` | `-` | `T ← S − T` | 4 | 8 |
| `13` | `mul` | `*` | `T ← S × T` (знаковое) | 4 | 8 |
| `14` | `div` | `/` | `T ← S / T` (знаковое, к нулю) | 4 | 8 |
| `15` | `mod` | `mod` | `T ← S mod T` | 4 | 8 |
| `16` | `and` | `and` | `T ← S & T` | 4 | 8 |
| `17` | `or` | `or` | `T ← S \| T` | 4 | 8 |
| `18` | `xor` | `xor` | `T ← S ^ T` | 4 | 8 |
| `19` | `eq` | `=` | `T ← (S = T) ? −1 : 0` | 7 | 11 |
| `1A` | `lt` | `<` | знаковое `S < T` | 7 | 11 |
| `1B` | `gt` | `>` | знаковое `S > T` | 6–9 | 10–13 |
| `1C` | `ult` | `u<` | беззнаковое `S < T` | 7 | 11 |
| `1D` | `shl` | `lshift` | `T ← S << T` | 4 | 8 |
| `1E` | `shr` | `rshift` | `T ← S >> T` (логический) | 4 | 8 |
| `20` | `load` | `@` | `T ← MEM[T]` | 3 | 7 |
| `21` | `store` | `!` | `MEM[T] ← S`, снять два значения | 9 | 22 |
| `30` | `jz addr` | `if`, `until`, `while` | переход, если `T = 0`; `T` снимается | 6–7 | 10–11 |
| `31` | `jmp addr` | `else`, `again`, `repeat` | безусловный переход | 1 | 5 |
| `32` | `jnz addr` | (`loop`) | переход, если `T ≠ 0`; `T` снимается | 6–7 | 10–11 |

Ожидания зависят от кеша:

| Обращение | Тактов |
|---|---|
| чтение, попадание | 1 |
| чтение, промах (загрузка строки из четырёх слов) | 40 |
| запись (сквозная) | 10 |
| порт ввода-вывода | 1 |

Поэтому в таблице выше в «мин. тактов» учтены только записи. Каждый промах при чтении (выборка инструкции или чтение данных) добавляет 39 тактов.

### Цикл `do ... loop` на уровне инструкций

Цикл со счётчиком хранит индекс в `R`, а предел под ним в памяти. Транслятор раскладывает конструкцию в последовательность обычных инструкций:

```text
do:      swap  >r  >r                    ; R = индекс, под ним предел
loop:    r>  push 1  add                 ; индекс + 1
         r@  over  =                     ; сравнить с пределом
         jnz done                        ; если равны, выйти
         >r  jmp body                    ; иначе вернуть индекс и повторить
done:    drop  r>  drop                  ; убрать индекс и предел
```

`i` это просто `r@`.

## Транслятор

Консольное приложение. Интерфейс командной строки:

```shell
python3 -m translation.translator <исходник.fs> <результат.bin>
```

Результат: бинарный образ памяти `<результат.bin>` и текстовый листинг `<результат.bin>.hex` в формате `<адрес> - <слово> - <мнемоника>`. Файлы, подключаемые через `include`, ищутся рядом с исходником.

### Этапы трансляции

1. **Токенизация** (`tokens.py`): текст режется на слова; комментарии `\` и `( )` отбрасываются; строки `s"` и `."` становятся отдельными токенами с видами `str` и `print`. Вид токена нужен, чтобы текст строки (например, `dup`) не принимался за слово.
2. **Компиляция** (`translator.py`): токены обрабатываются по порядку; ведётся словарь слов (имя → вид и адрес или значение). Вне определений числа накапливаются в стеке времени трансляции (нужны для `constant`, `allot`, `,`).
3. **Сборка образа** (`image.py`): определения и главная часть склеиваются, после кода добавляется секция данных, ссылки на данные заменяются настоящими адресами, адрес точки входа вписывается в первую инструкцию.
4. **Запись** образа и листинга.

### Правила генерации кода

| Конструкция | Результат |
|---|---|
| встроенное слово | одна инструкция или короткая последовательность (таблица `primitives.py`) |
| число | `push n`, либо `push <адрес литерала>; load` для чисел вне 24 бит |
| слово, определённое через `:` | `call <адрес слова>` |
| переменная, буфер | `push <адрес>` |
| константа | `push <значение>` |
| `s" ..."` | `push <адрес строки>` |
| `." ..."` | `push <адрес строки>; call pstr-type` |
| `' имя`, `[']` | `push <адрес слова>` |
| `if` / `else` / `then` | `jz` на метку `else` (или `then`), `jmp` на метку `then` |
| `begin` ... `until` | `jz <начало цикла>` |
| `begin` ... `again` | `jmp <начало цикла>` |
| `begin` ... `while` ... `repeat` | `jz <конец>` и `jmp <начало>` |
| `do` / `?do` / `loop` | последовательность из раздела выше; `?do` дополнительно проверяет `limit = start` и пропускает цикл |
| `recurse` | `call <адрес текущего слова>` |
| начало образа | `jmp <главная часть>` |
| конец главной части | `halt` (если нет `bye`) |

Адреса переходов вперёд неизвестны в момент генерации, поэтому транслятор запоминает позицию инструкции в стеке управляющих конструкций и позже «исправляет» её операнд (`if`, `else`, `then`, `while`, `repeat`, `?do`). Ссылки на данные (`DataRef`) разрешаются при сборке образа, когда известен размер кода.

### Пример

Исходник:

```forth
: sq dup * ;
5 ' sq execute
bye
```

Листинг:

```text
0000 - 31000010 - jmp 0x0010 ; entry
0004 - 01000000 - dup
0008 - 13000000 - mul
000c - 05000000 - ret
0010 - 0A000005 - push 5
0014 - 0A000004 - push 4
0018 - 09000000 - exec
001c - 00000000 - halt
```

`push 4` это `' sq` (адрес слова `sq`), `exec` это `execute`.

### Ошибки трансляции

Неизвестное слово, незакрытое определение или строка, несбалансированные `if`/`begin`/`do`, взятие адреса константы или встроенного слова, программа больше допустимого размера образа (`0xE000` байт). Сообщение содержит номер токена.

### DataPath

Реализован в классе `DataPath` (`components/data_path.py`). Результат АЛУ по общей шине поступает на входы всех регистров; другого способа переслать значение из регистра в регистр нет (используются проходы `passA`/`passB`). За такт по шине выходит один результат, который может быть защёлкнут сразу в несколько регистров.

**Мультиплексор A** (`mux_a_sel`):

| Код | Источник |
|---|---|
| 0 | операнд `IR` (24 бита со знаком, расширяется до 32) |
| 1 | `S` |
| 2 | `PC` |
| 3 | `SP` |
| 4 | `RSP` |
| 5 | `DR` |

**Мультиплексор B** (`mux_b_sel`):

| Код | Источник |
|---|---|
| 0 | `DR` |
| 1 | `R` |
| 2 | `T` |
| 3 | константа (выбирается `const_sel`) |
| 4 | `AR` |

**Константы** (`const_sel`): `0 → 0`, `1 → 1`, `2 → 4`, `3 → 8`.

**АЛУ** (`alu_op`):

| Код | Операция | Код | Операция |
|---|---|---|---|
| 0 | `A + B` | 6 | `A \| B` |
| 1 | `A − B` | 7 | `A ^ B` |
| 2 | `A × B` (знаковое) | 8 | `passA` (результат `A`) |
| 3 | `A / B` (знаковое, к нулю) | 9 | `passB` (результат `B`) |
| 4 | `A mod B` | 10 | `A << (B & 31)` |
| 5 | `A & B` | 11 | `A >> (B & 31)`, логический |

Деление на ноль останавливает моделирование с ошибкой.

**Флаги** (`SR`, защёлкиваются сигналом `latch_sr`): `N` (старший бит результата), `Z` (результат 0), `V` (знаковое переполнение), `C` (перенос при сложении, заём при вычитании).

**Регистры и защёлки.** `latch_s`, `latch_pc`, `latch_sp`, `latch_rsp`, `latch_r`, `latch_t`, `latch_ar`, `latch_ir`, `latch_sr` загружают значение с шины. Регистр `DR` имеет два источника: `latch_dr_alu` (с шины) или `latch_dr_mem` (данные, пришедшие из памяти).

### ControlUnit и микрокод

Реализован в классе `ControlUnit` (`components/control_unit.py`), тип управления: микропрограммный (`mc`).

**Составные части:**

| Блок схемы | Реализация |
|---|---|
| `mPC` | `ControlUnit.mpc` |
| `mIR` | `ControlUnit.mir`, текущая микрокоманда |
| память микропрограмм | `ControlUnit.rom`, 111 микрокоманд, загружается из `microcode/microcode.csv` |
| Instruction Decoder | `ControlUnit.decoder`: таблица «опкод → адрес в ROM», загружается из `decoder.csv`; метод `decoder_address()` |
| MUX следующего адреса | `get_next_mpc()`: `mPC+1`, поле `addr`, адрес из декодера |
| MUX условий | `condition_taken()`: флаги `Z`, `N`, `V`, `C` |
| Stall | переменная `waiting` в `tick()` |
| блок гашения защёлок | при `waiting` вызов `DataPath.tick` пропускается |

**Формат микрокоманды** (39 бит):

| Биты | Поле | Размер | Назначение |
|---|---|---|---|
| 0–10 | `latch_*` | 11 | `s, pc, sp, rsp, dr_alu, dr_mem, r, t, ar, ir, sr` |
| 11–13 | `mux_a_sel` | 3 | источник A |
| 14–16 | `mux_b_sel` | 3 | источник B |
| 17–18 | `const_sel` | 2 | константа |
| 19–22 | `alu_op` | 4 | операция АЛУ |
| 23 | `mem_rd` | 1 | запрос чтения |
| 24 | `mem_wr` | 1 | запрос записи |
| 25 | `halt` | 1 | остановка |
| 26–29 | `cond` | 4 | условие перехода |
| 30–38 | `addr` | 9 | адрес перехода внутри памяти микропрограмм |

**Условия перехода** (`cond`):

| Код | Имя | Переход на `addr`, если |
|---|---|---|
| 0 | `next` | никогда (следующий `mPC+1`) |
| 1 | `jmp` | всегда |
| 2 | `jz` | `Z = 1` |
| 3 | `jnz` | `Z = 0` |
| 4 | `jvs` | `V = 1` |
| 5 | `jvc` | `V = 0` |
| 6 | `jcs` | `C = 1` |
| 7 | `jcc` | `C = 0` |
| 8 | `jn` | `N = 1` |
| 9 | `jp` | `N = 0` |
| 10 | `jlv` | `N ≠ V` |
| 11 | `dispatch` | переход на начало микропрограммы инструкции по опкоду из `IR` |

Используются коды 0, 1, 2, 3, 6, 10, 11, остальные оставлены на расширение.

Исходная таблица: `microcode/microcode.csv`.

**Декодер:** 31 опкод, таблица в `microcode/decoder.csv` (опкод в hex, метка начала микропрограммы).

### Подсистема памяти и кеш

Реализована в классе `MemorySystem` (`memory/memory_system.py`). Интерфейс с микрокодом: `tick(AR, DR, mem_rd, mem_wr) → (данные, ready)`. Микрокод не знает ни о кеше, ни о задержках: он держит запрос, пока не придёт `ready`.

**Параметры кеша:**

| Параметр | Значение |
|---|---|
| Организация | единый кеш для инструкций и данных |
| Отображение | прямое (direct-mapped) |
| Размер | 64 строки по 4 слова (16 байт), всего 1 КиБ |
| Политика записи | сквозная (write-through), без загрузки строки при промахе записи |
| Попадание | 1 такт |
| Обращение к RAM | 10 тактов |
| Порты ввода-вывода | в обход кеша |

**Разбиение адреса:**

```text
 15      10 9       4 3     2 1  0
┌──────────┬─────────┬───────┬────┐
│ tag (6)  │ index(6)│ word  │ 00 │
└──────────┴─────────┴───────┴────┘
```

В программе тег хранится как `address >> 10`.

**Автомат состояний** (`State`): `IDLE` (ожидание запроса), `FILL` (заполнение строки, четыре слова по 10 тактов), `READ_RAM` (чтение при выключенном кеше), `WRITE_RAM` (запись в RAM).

| Случай               | Что происходит                                                             | Тактов |
| -------------------- | -------------------------------------------------------------------------- | ------ |
| чтение, попадание    | слово из кеша                                                              | 1      |
| чтение, промах       | очищается бит valid, четыре слова строки читаются из RAM, записывается тег | 40     |
| запись, попадание    | слово обновляется в кеше и в RAM                                           | 10     |
| запись, промах       | только запись в RAM                                                        | 10     |
| порт ввода-вывода    | обращение к регистру порта                                                 | 1      |

**Порты** (`IOPorts`): чтение порта ввода забирает следующий символ из входного буфера; если буфер пуст, возникает исключение `EOFError`, и моделирование останавливается. Запись в порт вывода добавляет символ в выходной буфер.

## Влияние кеша на производительность

Программа `linear_filter` вычисляет `Y[i] = 3·X[i] + 2·X[i−1] + X[i−2]` для массива `X`; каждый элемент читается несколько раз подряд (временная локальность), поэтому она подходит для демонстрации кеша. Для сравнения взята также сортировка пузырьком. Входные данные случайные, измерения детерминированы.

| Программа | N | Тактов без кеша | Тактов с кешем | Ускорение | Попаданий | Промахов | Доля попаданий |
|---|---|---|---|---|---|---|---|
| `linear_filter` | 10 | 44 141 | 33 167 | 1,33 | 2 176 | 287 | 88,3 % |
| `linear_filter` | 30 | 127 088 | 92 414 | 1,38 | 6 346 | 748 | 89,5 % |
| `linear_filter` | 100 | 429 128 | 308 864 | 1,39 | 21 516 | 2 446 | 89,8 % |
| `sort` | 10 | 98 548 | 57 091 | 1,73 | 5 323 | 215 | 96,1 % |
| `sort` | 30 | 783 711 | 404 616 | 1,94 | 43 695 | 472 | 98,9 % |
